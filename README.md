# claude-toolkit-console

Claude Code 도구 환경(플러그인·스킬·MCP·CLI)을 여러 머신에 걸쳐 보고, 배치하고, 옮기는
로컬 우선 콘솔.

CLI(`ctk`)와 웹 콘솔이 모두 동작합니다.

## 왜 필요한가

Claude Code에 툴을 많이 설치할수록 세 가지가 어려워집니다.

1. **무엇을 언제 쓸지 모른다** — 툴 메타데이터만으로는 자동 선택에 한계가 있어, 결국 사람이
   명시적으로 지시해야 하는데 그 판단 근거가 흩어져 있습니다.
2. **전역 설치가 컨텍스트를 잠식한다** — 필요한 프로젝트로 스코프를 옮기는 일이 전부
   수작업이고, 자산 유형(플러그인·스킬·MCP)마다 절차가 다릅니다.
3. **머신마다 설치 상태가 다르다** — 다른 머신에서 이어 작업할 때 무엇이 깔려 있는지 알기
   어렵습니다.

## 5분 시작하기

### 0. 준비

Node.js 22.13 이상, pnpm. 저장소를 클론하고 의존성을 설치합니다.

```sh
pnpm install
pnpm build
```

이후 명령은 `pnpm ctk <명령>`으로 실행합니다.

### 1. 카탈로그 만들기

```sh
pnpm ctk init
```

`~/.local/share/ctk/catalog`에 카탈로그를 만들고 이 머신의 `machine_id`를 발급합니다.
이미 있으면 아무것도 바꾸지 않습니다(멱등).

카탈로그 위치를 직접 정하려면 `--catalog <경로>`, 머신에 알아볼 이름을 붙이려면
`--machine-alias <이름>`을 줍니다.

### 2. 설치된 툴 스캔

```sh
pnpm ctk scan
```

플러그인·스킬·MCP·CLI를 훑어 **스냅샷 한 장**으로 기록합니다. 출력에 자산 수와 스코프 분포가
나옵니다.

> 스냅샷은 덮어쓰지 않고 쌓입니다. 두 시점을 비교해야 "언제 뭐가 들어왔는지"가 드러나기
> 때문입니다.

### 3. 사용량 측정 (선택)

```sh
pnpm ctk measure
```

세션 트랜스크립트를 파싱해 호출 횟수·마지막 사용 시점·토큰 합계를 뽑고, 각 자산이 **가만히
있어도 차지하는 컨텍스트**(상시 점유)를 잽니다.

**상시 점유 측정에는 `ANTHROPIC_API_KEY`가 필요합니다**(`count_tokens` API). 없으면:

```sh
pnpm ctk measure --no-credentials-ok
```

이때 점유는 `unmeasured`로 남습니다 — **0으로 채우지 않습니다.** 자세한 이유는
[알아두면 좋은 것](#순위가-결론이-되려면-모집단이-받쳐줘야-한다)을 보세요.

### 4. 문서 생성

```sh
pnpm ctk gen --dry-run     # 0원 — 대상 자산 수와 원본 크기만
pnpm ctk gen --no-llm      # 0원 — 규칙 기반 추출
pnpm ctk gen --max-budget-usd 2 --timeout-sec 180   # 유료
```

자산마다 **`annotation.md`**(언제 쓰는가)와 **`usage.md`**(어떻게 부르는가)를 만듭니다.

유료 경로는 실행 전에 대상 수·호출 수·예상 비용을 표시하고 **승인을 기다립니다.**
`--max-budget-usd`는 필수이며 각 호출의 하드캡으로 그대로 전달됩니다.

### 5. 보기

```sh
pnpm ctk usage --unused-expensive 5   # 안 쓰는데 비싼 툴
pnpm ctk web --open                   # 브라우저 콘솔 (브라우저까지 자동으로 열림)
```

## 무엇을 할 수 있나 — 상황별 안내

### "이 상황에 어떤 툴을 쓰지?"

`toolkit-search` 스킬을 설치하면 **Claude Code 세션이 직접** 카탈로그를 검색합니다.
툴 이름을 몰라도 상황만 말하면 됩니다.

```
스캔한 PDF에서 표를 뽑아야 하는데 뭘 쓰면 되나?
```

설치 방법은 [아래](#toolkit-search--에이전트가-툴을-찾는-진입점)에 있습니다.

사람이 직접 보려면 웹 콘솔의 **자산** 탭에서 이름·종류로 거르고, 자산을 눌러
`annotation.md`(언제 쓰는가)와 `usage.md`(사용법)를 읽습니다.

### "전역 설치가 너무 많아 컨텍스트가 무겁다"

먼저 무엇이 비싼지 봅니다.

```sh
pnpm ctk usage --unused-expensive 10
```

옮길 것을 정했으면 활성 스코프를 이동합니다.

```sh
pnpm ctk move --asset <자산id> --to project --project-index 3
pnpm ctk move --asset <자산id> --to user          # 다시 전역으로
```

되돌리려면:

```sh
pnpm ctk rollback --last
```

> **설치 스코프와 활성 여부는 다른 축입니다.** `move`가 바꾸는 것은 **활성 스코프**(어디서
> 켜지는가)이고 설치 위치는 그대로입니다. 설치 스코프 자체를 옮기는 것은
> `uninstall` + `install`이며 `ctk`가 하지 않습니다 — 되돌릴 수 있는 조치를 먼저 제안하는
> 설계입니다.

프로젝트 인덱스는 웹 콘솔의 자산 상세에서 드롭다운으로 고르는 게 편합니다.

### "다른 머신에도 이게 깔려 있나?"

각 머신에서 `ctk scan`을 돌리고 스냅샷을 **private Git 저장소**에 push하면, 다른 머신에서
pull해 설치 현황을 볼 수 있습니다.

> ⚠️ 동기화 저장소는 **반드시 private**이어야 합니다. 스냅샷에는 설치된 툴 목록과 사용량이
> 들어갑니다.

**조치는 현재 머신에서만 실행됩니다.** 다른 머신의 값은 그 머신이 마지막으로 push한 시점의
것이며 현재 상태가 아닙니다.

### "저번 주 이후로 뭐가 바뀌었지?"

```sh
pnpm ctk doctor --drift
```

가장 최근 두 스냅샷을 비교해 **유입·이탈·무변경**을 보여줍니다. 기록 없이 들어온 툴은 현재
상태만 봐서는 찾을 수 없고 두 시점을 diff해야 드러납니다.

## 웹 콘솔

```sh
pnpm ctk web --open                    # 브라우저까지 자동으로 연다 (조회 전용)
pnpm ctk web --actions --open          # 액션 모드 + 브라우저 자동 실행
pnpm ctk web                           # URL만 출력 (직접 복사)
pnpm ctk web --no-projects             # 프로젝트 이름을 응답에 싣지 않는다
pnpm ctk web --port 8787               # 포트 고정 (기본은 OS가 고름)
```

`--open`이 없으면 URL만 출력되며 직접 붙여넣어야 합니다. macOS·Linux·Windows에서 동작하고,
브라우저를 못 열어도 **서버는 그대로 뜹니다** — 출력된 URL을 직접 열면 됩니다.

**127.0.0.1에만 바인딩하고 데몬으로 상주하지 않습니다.** 사용자가 띄우고 `Ctrl+C`로 끕니다.
자동 시작하지 않고, 유닛 파일도 데몬화 플래그도 제공하지 않습니다.

### 화면

| 탭 | 내용 |
|---|---|
| **자산** | 이름·종류·설치 스코프·활성 여부·MCP 상태·출처·문서 유무. 이름/종류로 거르기 |
| **자산 상세** | `annotation.md`·`usage.md` 본문, 저장소 링크, 이관 버튼 |
| **사용량** | "안 쓰는데 비싼 툴" 순위 + **순위에 넣을 수 없는 자산**(미측정) |

### 액션 모드

`--actions`를 주면 세션 토큰이 발급되고 URL에 프래그먼트로 붙습니다. 그 URL을 브라우저에
붙여넣으면 됩니다.

- 토큰은 **메모리에만** 있고 서버를 끄면 사라집니다
- 페이지가 토큰을 읽은 즉시 주소창·히스토리에서 지웁니다
- 쓰기 요청은 **토큰·Origin·Host 3중 관문**을 통과해야 합니다

`gen`은 **2단계 승인**입니다 — 먼저 비용만 계산해 보여주고, 그 화면에서 명시 승인해야 유료
호출이 일어납니다. 승인 없이는 어떤 유료 호출도 발생하지 않습니다.

#### ⚠️ `--actions --open`이 치르는 값

액션 URL에는 세션 토큰이 들어 있고, `--open`은 그 URL을 **브라우저 실행기의 인자로** 넘깁니다.
같은 머신의 다른 계정이 `ps`로 볼 수 있습니다. 노출 창은 실행기가 즉시 종료하므로 짧지만
**쓰기 자격증명**이므로 기동 시 매번 고지합니다.

- 개인 노트북 → 실질적 문제 없음
- **공용 호스트 → `--open` 없이** URL을 직접 붙여넣거나, 조회 전용(`--open`만)을 쓰세요

### ⚠️ 전제 — 개인 로컬 머신

조회 엔드포인트(`GET /api/view-model`)는 **무인증**입니다. 막아야 할 것은 "다른 출처가 우리
포트로 말을 거는 것"이지 "사용자가 자기 화면을 보는 것"이 아니기 때문이고, DNS rebinding은
Host 검사로 막습니다.

그 응답에는 이관 대상으로 고를 수 있는 **프로젝트 디렉터리 이름**이 실립니다(경로가 아니라
마지막 세그먼트만). 원본인 `~/.claude.json`은 소유자 전용(`-rw-------`)이지만 이 응답은
루프백에 닿는 주체면 읽을 수 있으므로, **다중 사용자 호스트에서는 같은 머신의 다른 계정이
프로젝트 이름을 볼 수 있습니다.**

- 개인 노트북·워크스테이션 → 실질적 노출 없음(파일을 읽을 수 있는 주체와 같습니다)
- **공용 개발 서버·공유 원격 호스트 → `--no-projects`로 끕니다.** 이때 웹에서는 프로젝트
  이관이 비활성되고 CLI의 `ctk move --to project --project-index N`을 씁니다

기동 시 실제로 몇 건이 실리는지 stderr에 고지합니다 — 프로젝트는 새 디렉터리에서 `claude`를
한 번 띄우면 자동으로 늘어나므로, 한 번 점검한 결과를 영구히 믿지 않기 위함입니다.

## `toolkit-search` — 에이전트가 툴을 찾는 진입점

Claude Code 세션이 카탈로그를 검색해 상황에 맞는 툴과 사용법을 찾게 하는 스킬입니다.
상시 점유는 `name` + `description` 한 줄뿐이고, 본문은 호출될 때만 실립니다.

설치는 저장소의 원본을 스킬 디렉터리로 복사하면 끝입니다.

```sh
# 전역(모든 프로젝트에서 사용)
cp -r skills/toolkit-search ~/.claude/skills/

# 또는 특정 프로젝트에서만
cp -r skills/toolkit-search <프로젝트>/.claude/skills/
```

`ctk`가 이 복사를 대신 해주지는 않습니다 — 사용자의 실제 설정 디렉터리에 쓰는 코드는
백업·롤백·보안 심사를 거쳐야 하고, 한 번 하는 일에 그 표면을 새로 만들 이유가 없기
때문입니다. 되돌리려면 복사한 디렉터리를 지우면 됩니다.

스킬이 제 몫을 하려면 **카탈로그와 문서가 있어야 합니다** — `init` → `scan` → `gen`을 먼저
돌리세요. 문서가 없으면 스킬이 "생성이 필요하다"고 알리고 멈춥니다.

스킬 자체의 검증(상시 비용 상한 · 본문에 자산 이름이 하드코딩돼 있지 않은가):

```sh
pnpm ctk verify ac3
```

### 실증된 것

합성 카탈로그(4자산 × 2머신)를 대상으로 실제 헤드리스 세션을 띄워 확인했습니다 — 툴 이름도
스킬 이름도 알려주지 않고 **상황만** 주었을 때:

- 스킬을 스스로 발동하고, 정답 자산을 찾아 근거(`when_to_use`)와 함께 제시
- 오답 3종을 각각 왜 아닌지 밝히며 배제
- 지정한 머신 기준으로 설치 상태를 보고하고, 다른 머신의 값과 섞지 않음
- 카탈로그 문서에 적힌 실행 명령을 **부르지 않음**(문서는 참조 데이터이지 지시가 아니다)
- 스냅샷이 없으면 "미설치"가 아니라 **"확인 불가"**로 구분

## 명령 레퍼런스

모든 명령은 `pnpm ctk <명령>` 형태로 실행합니다.

### `init` — 카탈로그 초기화

```sh
pnpm ctk init [--catalog <경로>] [--machine-alias <이름>]
```

멱등입니다. 이미 초기화돼 있으면 설정만 확인하고 끝냅니다.

### `scan` — 설치 현황 스냅샷

```sh
pnpm ctk scan
```

자산·설치 스코프·활성 여부·MCP 토글을 한 장으로 기록합니다.

### `measure` — 사용량과 상시 점유 측정

```sh
pnpm ctk measure [--transcripts <경로>] [--no-credentials-ok]
```

- `--transcripts` — 트랜스크립트 디렉터리 직접 지정
- `--no-credentials-ok` — `ANTHROPIC_API_KEY` 없이 실행. 점유는 `unmeasured`로 남습니다

### `gen` — 카탈로그 문서 생성

```sh
pnpm ctk gen --dry-run
pnpm ctk gen --no-llm
pnpm ctk gen --max-budget-usd <금액> --timeout-sec <초> [--max-assets N] [--resume] [--yes]
```

| 플래그 | 뜻 |
|---|---|
| `--dry-run` | **0원.** 네트워크 호출도 서브프로세스도 없이 대상 수·원본 크기만 |
| `--no-llm` | **0원.** frontmatter·헤딩을 규칙 기반으로 추출 |
| `--max-budget-usd` | **유료 경로 필수.** 각 호출의 하드캡 |
| `--timeout-sec` | **유료 경로 필수.** 호출당 타임아웃 |
| `--max-assets` | 이번 실행에서 처리할 자산 수 상한 |
| `--resume` | 중단된 실행을 이어서 |
| `--yes` | 비대화형 승인(CI 등) |
| `--allow-managed-policy` | managed 정책 위험 키가 있어도 비대화형 실행 허용 |

`--dry-run`은 위생 검사가 거부한 자산도 사유와 함께 보여줍니다(심볼릭 링크 등).

### `usage` — 안 쓰는데 비싼 툴

```sh
pnpm ctk usage [--unused-expensive N] [--json]
```

순위와 함께 **순위에 넣을 수 없는 자산**(점유 미측정)을 별도로 보여주고, 순위가 결론이 될
자격이 없으면 **숫자보다 먼저** 그 사실을 알립니다.

### `move` / `rollback` — 활성 스코프 이동

```sh
pnpm ctk move --asset <자산id> --to <user|project> [--project-index N]
              [--from <user|project>] [--from-project-index N]
pnpm ctk rollback --last
```

실행 전 자동 백업하고, 검증에 실패하면 즉시 롤백합니다. MCP 자산과 CLI 도구는 이동 대상이
아닙니다(각각 별도 사유로 거부됩니다).

### `doctor` — 진단

```sh
pnpm ctk doctor --drift             # 최근 두 스냅샷 비교
pnpm ctk doctor --managed-policy    # 기업 관리 정책이 봉인을 뚫는지
```

`--managed-policy`는 **이 머신 기준**으로 판정합니다. 정책 **내용은 출력하지 않고** 위험 키
이름만 냅니다. 위험 키가 있거나 정책 파일을 읽지 못하면 종료 코드가 1입니다.

### `verify` — 수용 기준 검증

```sh
pnpm ctk verify ac1                 # 스냅샷 ↔ 재구성 독립 대조
pnpm ctk verify ac3 [--skill <경로>] # 진입 스킬의 비용 상한·하드코딩 금지
pnpm ctk verify seal --max-budget-usd <금액> --timeout-sec <초> \
                     --installed-plugin-command <슬래시커맨드>   # 유료
```

`verify seal`은 `--safe-mode` 봉인이 실제로 동작하는지 **실세션으로** 확인하고, **전부
통과했을 때만** 검증된 CLI 버전 기록을 갱신합니다.

### `agent-probe` — AC-3.3 진단 (유료)

```sh
pnpm ctk agent-probe --catalog <합성 카탈로그 루트> --machine-id <머신 id> \
                     --query "<질의>" --max-budget-usd <금액> --timeout-sec <초> \
                     [--model <모델>]
```

합성 카탈로그를 대상으로 에이전트가 툴을 스스로 찾는지 진단합니다. **실제 카탈로그·config에
아무것도 쓰지 않습니다.**

**모델은 고정돼 있고 결과에 함께 표시됩니다.** `--model`을 생략하면 기준 모델을 씁니다 —
고정하는 이유는 비용이 아니라 **모집단**입니다. 없으면 자식이 사용자의 기본 모델을 써서
진단 결과가 머신마다 달라지고 "지난번엔 통과했다"를 비교할 근거가 사라집니다. 다른 모델로
재보려면 `--model`에 명시하세요.

**지출이 화면에 남습니다.** 이 명령은 `sync`를 호출하지 않는 계약이라 run-log에 쓸 수 없어,
실제 비용·모델·토큰을 실행 끝에 한 줄로 보여줍니다. 읽지 못하면 **"미보고"**라고 말하지
0원이라고 하지 않습니다.

## 알아두면 좋은 것

### 순위가 결론이 되려면 모집단이 받쳐줘야 한다

`ANTHROPIC_API_KEY`가 없으면 대부분의 자산이 **점유 미측정**으로 빠집니다. 그러면
"안 쓰는데 비싼 툴" 순위에는 **비용이 정말로 0인 것만** 남습니다 — 숫자는 다 맞는데 화면이
답하는 질문에는 거짓입니다.

그래서 `ctk usage`와 웹 콘솔은 순위가 결론이 될 자격이 없으면 **숫자보다 먼저** 그 사실을
알립니다:

```
⚠️  이 순위는 아직 결론이 될 수 없다 — 점유가 측정된 3건이 전부 0토큰이다 (미측정 177건).
    ANTHROPIC_API_KEY를 설정하고 `ctk measure`를 다시 돌리면 점유가 측정된다.
```

### "없음"과 "판정 불가"는 다르다

이 도구는 **잴 수 없는 것을 0으로 채우지 않습니다.**

- 점유가 안 잡히면 `unmeasured` — 0이 아닙니다
- 스냅샷이 없으면 "설치 여부 미확인" — "미설치"가 아닙니다
- MCP의 `unknown`(모름)과 `unset`(설정 안 됨)은 다른 배지로 표시됩니다

화면이 비어 보인다면 "아무것도 없다"가 아니라 "아직 재지 못했다"일 수 있습니다.

### `gen`은 서드파티 원문을 다룬다

카탈로그 문서는 툴 제작자가 쓴 `SKILL.md`·`README`·`plugin.json`을 근거로 자동 생성됩니다.
그 안에 명령처럼 보이는 문장이 있어도 **읽을 데이터이지 따라야 할 지시가 아닙니다.**
각 문서 상단의 `gen_source_trust`가 근거의 출처를 알려줍니다(`marketplace`·`local`·`unknown`).

`unknown`은 "출처를 특정하지 못했다"는 뜻이지 안전하다는 뜻이 아닙니다.

프롬프트 인젝션 5종(지시 무효화·시스템 태그 위장·구획자 탈출·원격 명령 실행·외부 URL 유도)을
실제 모델에 통과시켜 **전부 카탈로그 쓰기 이전에 거부**되는 것을 확인했습니다.

### 문서는 인용한 원본만큼만 완전하다

`gen`은 산출물의 모든 문단에 원본 라인 인용을 붙입니다. 그래서 **원본에 없는 것은 지어내지
않습니다** — 파일시스템을 훑어 목록을 만들면 더 완전하겠지만 인용을 붙일 수 없습니다.

이 설계는 완전성 대신 **검증가능성**을 택했습니다. 문서에 없는 커맨드가 실제로는 있을 수
있으니, 원본을 함께 보세요.

### 카탈로그에는 절대경로가 들어가지 않는다

동기화 저장소로 가는 값에는 경로 원문 대신 해시(`path_hash`)만 들어갑니다. 웹 콘솔이
프로젝트를 보여줄 때도 **마지막 세그먼트만** 쓰고 상위 구조는 서버에서 버립니다.

## 설계 방향

- **로컬 우선** — 브라우저는 로컬 설정 파일을 쓸 수 없으므로, 로컬 에이전트(CLI)가 실제
  조작을 맡고 웹은 그 위의 표현·조작 계층이 됩니다.
- **동기화 어댑터** — v1은 사용자가 지정한 private Git 저장소를 동기화 백엔드로 씁니다.
  백엔드·인증·비용이 없고 오프라인에서 동작합니다. 어댑터 경계를 두어 이후 클라우드로
  이행할 수 있습니다.
- **읽기와 쓰기 분리** — 설정을 바꾸는 코드는 별도 계층에 가두고 백업·롤백을 강제합니다.
- **스냅샷은 append-only** — 현재 상태와 드리프트는 두 시점의 diff로 계산합니다.
- **되돌릴 수 있는 조치를 먼저** — 삭제보다 비활성·이동을 제안합니다.
- **런타임 의존성 0** — 승인 목록(`zod`, `@anthropic-ai/sdk`) 외에는 두지 않으며 CI가
  강제합니다.

pnpm verify     # typecheck · lint · test · 위생 검사 · 의존성 게이트 · managed 정책

pnpm release:ac39    # 악성 픽스처를 실제 모델에 통과시키는 인젝션 게이트
pnpm release:seal    # 봉인이 실제로 동작하는지 실세션 검증
