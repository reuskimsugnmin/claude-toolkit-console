# claude-toolkit-console

Claude Code 도구 환경(플러그인·스킬·MCP·CLI)을 여러 머신에 걸쳐 보고, 배치하고, 옮기는
로컬 우선 웹 콘솔.

> 🚧 **개발 중입니다.** CLI(`ctk`)는 동작하고, 웹 콘솔은 아직 없습니다.

## 왜 필요한가

Claude Code에 툴을 많이 설치할수록 세 가지가 어려워집니다.

1. **무엇을 언제 쓸지 모른다** — 툴 메타데이터만으로는 자동 선택에 한계가 있어,
   결국 사람이 명시적으로 지시해야 하는데 그 판단 근거가 흩어져 있습니다.
2. **전역 설치가 컨텍스트를 잠식한다** — 필요한 프로젝트로 스코프를 옮기는 일이 전부 수작업이고,
   자산 유형(플러그인·스킬·MCP)마다 절차가 다릅니다.
3. **머신마다 설치 상태가 다르다** — 다른 머신에서 이어 작업할 때 무엇이 깔려 있는지 알기 어렵습니다.

## 설계 방향

- **로컬 우선** — 브라우저는 로컬 설정 파일을 쓸 수 없으므로, 로컬 에이전트(CLI)가 실제 조작을 맡고
  웹은 그 위의 표현·조작 계층이 됩니다.
- **동기화 어댑터** — v1은 사용자가 지정한 private Git 저장소를 동기화 백엔드로 씁니다.
  백엔드·인증·비용이 없고 오프라인에서 동작합니다. 어댑터 경계를 두어 이후 클라우드로 이행할 수 있습니다.
- **읽기와 쓰기 분리** — 설정을 바꾸는 코드는 별도 계층에 가두고 백업·롤백을 강제합니다.
- **스냅샷은 append-only** — 현재 상태와 드리프트는 두 시점의 diff로 계산합니다.
  기록 없이 유입된 툴은 현재 상태만 봐서는 드러나지 않습니다.

## `toolkit-search` — 에이전트가 툴을 찾는 진입점

Claude Code 세션이 카탈로그를 검색해 상황에 맞는 툴과 그 사용법을 찾게 하는 스킬입니다.
상시 점유는 `name` + `description` 한 줄뿐이고, 본문은 호출될 때만 실립니다.

설치는 저장소의 원본을 스킬 디렉터리로 복사하면 끝입니다.

```sh
# 전역(모든 프로젝트에서 사용)
cp -r skills/toolkit-search ~/.claude/skills/

# 또는 특정 프로젝트에서만
cp -r skills/toolkit-search <프로젝트>/.claude/skills/
```

`ctk`가 이 복사를 대신 해주지는 않습니다 — 사용자의 실제 설정 디렉터리에 쓰는 코드는
백업·롤백·보안 심사를 거쳐야 하고(`CLAUDE.md`의 안전 원칙), 한 번 하는 일에 그 표면을
새로 만들 이유가 없기 때문입니다. 되돌리려면 복사한 디렉터리를 지우면 됩니다.

설치 후 스킬이 제 몫을 하려면 카탈로그가 있어야 합니다:

```sh
pnpm ctk init      # 로컬 카탈로그 생성 (~/.local/share/ctk/catalog)
pnpm ctk scan      # 설치된 툴을 스냅샷으로 기록
pnpm ctk gen       # 자산별 사용법·주석 문서 생성 (LLM 사용 — 비용 사전 고지)
```

`ctk gen`은 유료 세션을 띄우므로 실행 전 대상 자산 수와 예상 비용을 표시하고 승인을
기다립니다. 인증이 없는 환경에서는 `ctk gen --no-llm`이 frontmatter와 README 헤딩을
규칙 기반으로 추출해 카탈로그를 채웁니다.

스킬 자체의 검증(상시 비용 상한 · 본문에 자산 목록이 없는가)은 다음으로 확인합니다:

```sh
pnpm ctk verify ac3
```

## 상태

`ctk init → scan → measure → gen → usage`와 `move → rollback` 왕복이 동작합니다.
남은 것은 웹 콘솔입니다.
